## ⚠️ Critical Architecture Rules

### Rule 1 — NO Master LangGraph Graph
There is **no single graph connecting all agents**. Each agent is an independent LangGraph workflow. Orchestration is done by FastAPI endpoints calling agents sequentially. **Do NOT create a master graph.**

### Rule 2 — Session Plan is Sacred
`Session.session_plan` (JSONB) is the **single source of truth** for the interview. It is generated by Planner + Orchestrator and consumed by the Interviewer. Its structure must match `InterviewPlan` / `InterviewAnchor` Pydantic schemas exactly.

### Rule 3 — Anchor Types Drive Everything
The `anchor.type` field (`"project" | "skill" | "gap" | "soft_skill"`) controls:
- Whether Qdrant is queried (skip for `"project"`)
- Which rubric weights are used for scoring
- Which evaluation mode is applied (`llm_only` vs `hybrid_similarity`)
- Do NOT add new anchor types without updating the evaluator rubric weights in `evaluator.py`

### Rule 4 — Evaluation Happens Asynchronously
The Evaluator is **NOT** an LangGraph agent. It is a **Celery task** (`tasks/evaluate.py`). It is triggered from `save_exchange_node` in the Interviewer. Do not call `evaluate_exchange()` directly from the WebSocket or FastAPI routes — always go through Celery.

### Rule 5 — Auth Uses localStorage, Not Cookies
JWT is stored in `localStorage` under the key `"token"`. The `Authorization: Bearer <token>` header is added automatically by `lib/api.ts`. Do NOT use cookie-based auth or `httpOnly` cookies.

### Rule 6 — Resume is the Central Entity
Sessions are linked to `Resume`, not `CandidateProfile`. `CandidateProfile` is deprecated. Always use `resume_id` for new session-related code.

### Rule 7 — Hybrid Scoring Requires reference_answer
The semantic similarity scoring only activates when:
- `anchor.evaluation_mode == "hybrid_similarity"` AND
- `anchor.reference_answer` is non-empty
If either is missing, the evaluator silently falls back to LLM-only scoring.

## 🐛 Known Bugs & Issues

### 1. Strengths Profile Radar Chart (Dashboard)
**Status:** Backend is correct, but the chart shows empty when no completed reports exist.  
**Root cause:** `strengths_profile` data comes from `Report.competency_breakdown`. If the user has never completed an interview (or reports were never generated), the array is empty.  
**Fix needed:** Show placeholder/fallback radar chart UI when `strengths_profile.length === 0`.

### 2. Double Question Bug (FIXED)
**Status:** Fixed in commit `ef947b1`.  
**Root cause:** The Planner's `opening_statement` was concatenated with the first anchor's `opening_question`, resulting in two questions.  
**Fix applied:** Replaced `opening_statement` with a static greeting in `open_interview_node`.

### 3. Orchestrator Fallback (Expected Behavior)
If Qdrant is empty (not seeded), all anchors will have `source = "planner_generated"` and `evaluation_mode = "llm_only"`. Run the seed script to populate Qdrant.


## 🧠 LLM Configuration

All LLM calls in agents use:
```python
from app.agents.profile_analyzer import _get_llm, _invoke_with_retries

llm = _get_llm()  # returns ChatGroq(model="llama-3.3-70b-versatile")
structured_llm = llm.with_structured_output(MyPydanticSchema)
result = _invoke_with_retries(structured_llm, prompt_string)
```

Do NOT create new LangChain/Groq instances — always use `_get_llm()` for consistency and to benefit from existing retry logic.

## 📐 Naming Conventions

| Item | Convention | Example |
|---|---|---|
| Python files | snake_case | `interview_planner.py` |
| Python functions | snake_case | `run_interview_planner()` |
| Python classes | PascalCase | `InterviewAnchor` |
| TypeScript files | PascalCase (components) or camelCase | `MatchDashboard.tsx`, `api.ts` |
| TypeScript interfaces | PascalCase | `DashboardStats` |
| API routes | kebab-case | `/match-analysis`, `/extract-job-url` |
| DB tables | snake_case plural | `candidate_profiles`, `match_cache` |
| Git commits | Conventional Commits | `feat(agent): ...`, `fix(ws): ...` |
