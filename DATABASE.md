# InterviewAI — Database Schema

> Read `CONTEXT.md` first. All models are in `backend/app/models/orm.py`.

---

## ORM Models (SQLAlchemy 2.0, PostgreSQL)

### `users`
| Column | Type | Notes |
|---|---|---|
| `id` | UUID PK | auto-generated |
| `email` | String(255) | unique, indexed |
| `hashed_password` | String(255) | bcrypt |
| `created_at` | DateTime(tz) | |
| `updated_at` | DateTime(tz) | auto-updated |

**Relationships:** `profiles`, `sessions`, `resumes` (all cascade delete)

---

### `resumes`
The **central entity** — a user can have multiple CVs. Sessions are linked to resumes, not profiles.

| Column | Type | Notes |
|---|---|---|
| `id` | UUID PK | |
| `user_id` | UUID FK → users | cascade delete |
| `filename` | Text | original file name |
| `cv_text` | Text | extracted plain text |
| `file_hash` | Text | SHA-256, indexed, unique per user |
| `analyzed_profile` | JSONB | output of Profile Analyzer agent |
| `is_analyzed` | Boolean | False until Profile Analyzer completes |
| `created_at` | DateTime(tz) | |
| `updated_at` | DateTime(tz) | |

**Unique constraint:** `(user_id, file_hash)` — prevents duplicate uploads  
**Relationships:** `sessions`, `match_caches`

---

### `match_cache`
Caches JD-to-CV match analysis to avoid re-running the Match Analyzer.

| Column | Type | Notes |
|---|---|---|
| `id` | UUID PK | |
| `resume_id` | UUID FK → resumes | cascade delete |
| `jd_hash` | Text | SHA-256 of job description text |
| `jd_text` | Text | original job description |
| `match_report` | JSONB | full output from Match Analyzer |
| `created_at` | DateTime(tz) | |

**Unique constraint:** `(resume_id, jd_hash)`

---

### `sessions`
Represents one full interview simulation.

| Column | Type | Notes |
|---|---|---|
| `id` | UUID PK | |
| `user_id` | UUID FK → users | cascade delete |
| `resume_id` | UUID FK → resumes | cascade delete |
| `profile_id` | UUID FK → candidate_profiles | **DEPRECATED** |
| `job_description` | Text | optional |
| `interview_type` | Enum | `technical \| behavioral \| mixed` |
| `status` | Enum | `pending \| active \| completed \| cancelled` |
| `session_plan` | JSONB | full hybrid InterviewPlan (Planner + Orchestrator output) |
| `started_at` | DateTime(tz) | |
| `ended_at` | DateTime(tz) | |

**Relationships:** `exchanges` (ordered by `turn_number`), `report` (one-to-one)

#### `session_plan` JSONB structure:
```json
{
  "candidate_name": "...",
  "role": "...",
  "total_duration_minutes": 30,
  "opening_anchor_id": "anchor-1",
  "opening_statement": "...",
  "closing_statement": "...",
  "anchors": [
    {
      "id": "anchor-1",
      "type": "skill",
      "title": "Python Async",
      "cv_reference": "...",
      "jd_relevance": "...",
      "opening_question": "Can you explain asyncio in Python?",
      "reference_answer": "asyncio is...",
      "what_to_listen_for": ["..."],
      "follow_up_directions": ["..."],
      "red_flags": ["..."],
      "time_allocation_minutes": 5,
      "priority": 1,
      "position_in_flow": "core",
      "source": "qdrant_rag",
      "evaluation_mode": "hybrid_similarity"
    }
  ]
}
```

---

### `exchanges`
One row per interviewer question + candidate answer turn.

| Column | Type | Notes |
|---|---|---|
| `id` | UUID PK | |
| `session_id` | UUID FK → sessions | cascade delete |
| `turn_number` | Integer | 1-indexed |
| `question` | Text | the question that was asked |
| `candidate_answer` | Text | candidate's response |
| `audio_url` | String(1024) | MinIO URL if voice mode |
| `response_time_sec` | Float | how long candidate took to answer |
| `react_scratchpad` | Text | LLM's internal reasoning (OBSERVE/ASSESS/DECIDE) |
| `created_at` | DateTime(tz) | |

**Relationship:** `evaluation` (one-to-one)

---

### `evaluations`
One evaluation per exchange, created asynchronously by Celery.

| Column | Type | Notes |
|---|---|---|
| `id` | UUID PK | |
| `exchange_id` | UUID FK → exchanges | unique, cascade delete |
| `score_accuracy` | Float | 0-10, hybrid (LLM 60% + similarity 40%) |
| `score_depth` | Float | 0-10, LLM only |
| `score_clarity` | Float | 0-10, LLM only |
| `score_star` | Float | 0-10, STAR method (behavioral only) |
| `feedback` | Text | 2-3 sentences shown to candidate |
| `improvement_tips` | JSONB | list of actionable tips |

---

### `reports`
One report per completed session, generated by Celery.

| Column | Type | Notes |
|---|---|---|
| `id` | UUID PK | |
| `session_id` | UUID FK → sessions | unique, cascade delete |
| `global_score` | Float | weighted average 0-10 |
| `competency_breakdown` | JSONB | `{category: {score, insights}}` |
| `action_plan` | Text | personalized improvement roadmap |
| `pdf_url` | String(1024) | MinIO download URL |
| `generated_at` | DateTime(tz) | |

#### `competency_breakdown` JSONB structure (drives the Strengths Profile radar chart):
```json
{
  "python": {"score": 8.5, "insights": "Strong async knowledge..."},
  "system_design": {"score": 6.0, "insights": "Could improve..."},
  "communication": {"score": 7.5, "insights": "Clear and structured..."}
}
```

---

### `candidate_profiles` (DEPRECATED)
Old profile model. `Resume.analyzed_profile` now serves this purpose. Field `profile_id` in Session still exists but is marked DEPRECATED.

## Pydantic Schemas (`backend/app/models/schemas.py`)

Key schemas for API input/output:

| Schema | Used for |
|---|---|
| `SessionCreate` | `POST /sessions/` body |
| `SessionResponse` | API response for session |
| `InterviewAnchor` | Part of `InterviewPlan` |
| `InterviewPlan` | Full plan schema with anchors list |
| `EvaluationResponse` | Evaluation API response |
| `ReportResponse` | Report API response |
| `DashboardStatsResponse` | `GET /dashboard/stats` response |
| `StrengthsProfile` | `{category: str, score: float}` — radar chart data |
| `ScoreEvolution` | `{date: str, score: float}` — line chart data |
